## Issue #200 — [FIXED] GAP-73: Ledger consistency verifier fails in fresh dev environments

**Priority:** P1 — Blocks release gate in fresh checkouts
**Files:**
- `scripts/verify-runtime-ledger-consistency.mjs`
- `scripts/verify-release-gate.mjs`

**Problem:** When `NEXT_PUBLIC_ENABLE_DB_LEDGER` is not set to `true` (the default),
`rootwork-ledger.db` is not expected to exist. The consistency verifier treated a missing DB
file as a hard failure (exit code 1) regardless of the flag state, blocking the entire
release gate on any fresh development environment.

**Root cause:** The verifier assumed DB presence was always required, without checking the
feature flag that governs whether SQLite is even enabled.

**Fix:**
- `verify-runtime-ledger-consistency.mjs`: When DB file is missing AND `NEXT_PUBLIC_ENABLE_DB_LEDGER != "true"`, skip gracefully (pass with warning) rather than fail
- `verify-release-gate.mjs`: Updated skip-detection logic to only treat a skipped consistency check as a gate failure when the flag is enabled

**Invariant upheld:** If `NEXT_PUBLIC_ENABLE_DB_LEDGER=true` but the DB is missing, the check still fails (correct behavior — production should have the DB).

**Status:** ✅ Fixed in this pass

## Issue #201 — GAP-74: Inline role helper functions in API routes duplicate routeAccess constants

**Priority:** P2 — Code quality / DRY violation
**Files:**
- `app/api/ledger/records/route.ts` (lines 11–17: `isLearnerRole`, `isFacilitatorRole`)
- `app/api/orchestration/worker-run/route.ts` (line 146: inline role array)
- Other API routes with ad hoc role string comparisons

**Problem:** Several API routes define inline helper functions like `isLearnerRole()` and
`isFacilitatorRole()` instead of importing the already-exported constants from
`lib/auth/routeAccess.ts` (`LEARNER_ROLES`, `FACILITATOR_ROLES`). This creates:
1. DRY violation — role membership is defined in two places
2. Drift risk — if a new role is added to a group, the inline helpers won't be updated automatically

**Fix:** Replace inline role helpers with imports from `lib/auth/routeAccess`:
```typescript
import { LEARNER_ROLES, FACILITATOR_ROLES } from "@/lib/auth/routeAccess";
// Instead of:
// function isLearnerRole(role) { return role === "student_independent" || ... }
```

**Test plan:**
- [ ] All updated routes still return correct 403 for unauthorized roles
- [ ] `npm run verify:release-gate` passes

**Status:** 🔲 Open — P2, schedule in next sprint

## Issue #202 — GAP-75: Orchestration worker-run auth check hardcodes role list

**Priority:** P2 — Code quality / DRY violation
**File:** `app/api/orchestration/worker-run/route.ts:146`

**Problem:** The auth guard hardcodes 4 role strings:
```typescript
if (!role || (role !== "admin" && role !== "super_admin" && role !== "teacher" && role !== "professional_development")) {
```
Should use `FACILITATOR_ROLES` and `ADMIN_ROLE` exports from `lib/auth/routeAccess.ts`.

**Fix:**
```typescript
import { FACILITATOR_ROLES, ADMIN_ROLE, SUPER_ADMIN_ROLE } from "@/lib/auth/routeAccess";
const ALLOWED_ROLES = new Set([...FACILITATOR_ROLES, ...ADMIN_ROLE, ...SUPER_ADMIN_ROLE]);
if (!role || !ALLOWED_ROLES.has(role)) { ... }
```

**Status:** 🔲 Open — P2, schedule in next sprint
